Privacy Policy

Friday — last updated 27 September 2026

Scope

This policy covers the application Friday (the “Application”), a private automation tool used by a single individual to access their own Google Workspace account. The Application is not a public service, has no other users, and does not process data belonging to anyone but its owner.

What Google user data the Application accesses

  • gmail.readonly — read and search the owner's email.
  • gmail.modify — create draft messages and apply labels.
  • gmail.send — send email, only on the owner's explicit instruction.
  • calendar — read and create the owner's calendar events.
  • drive — locate and upload files in the owner's Drive.
  • spreadsheets, documents — read and write the owner's own Sheets and Docs.
  • contacts.readonly — resolve the owner's contacts when addressing mail.

How the data is used

Data is used solely to carry out tasks the owner requests in their own session — for example, summarising an inbox, drafting a reply for the owner to review, or adding an event to the owner's calendar. The Application performs no profiling, no advertising, and no automated decision-making about any person.

Where the data is stored

All processing happens on a self-hosted machine owned and operated by the owner. OAuth credentials are stored on that same machine in a file readable only by the owner's operating-system account, with directory permissions restricted to that account.

Third-party sharing

None. Google user data is not sold, rented, transferred, disclosed, or transmitted to any third party, and is not used to train machine-learning models. The Application makes no outbound connections to any server operated by its author. Requests to Google APIs travel directly from the owner's machine to Google.

Limited use

The Application's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Data retention and deletion

Google data is retained on the owner's machine only as long as it is useful for the task at hand. The owner can delete all stored data at any time by removing the credential file and the Application's local data directory.

Access can be revoked at any time at myaccount.google.com/permissions, which immediately invalidates the stored credentials and ends all access. No further data is requested or retained after revocation.

Security

Credentials never leave the owner's machine. The Application requests only the scopes required for the features the owner uses, and does not request broader access than necessary.

Changes to this policy

Any change will be published on this page with an updated date. Continued use of the Application after a change constitutes acceptance of it.
